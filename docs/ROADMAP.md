## Перед публичной публикацией

### Подготовить руководство по подключению стороннего кодека

Руководство должно позволять разработчику добавить просмотр нового формата без изменения основного просмотрщика, если формат можно надёжно распознать по содержимому файла.

В документе необходимо подробно описать:

1. **Роль компонентов и расположение файлов**
   - основной модуль `FarRideViewer.dll` отвечает за интерфейс Far Manager, окно просмотра и загрузку изображений;
   - кодеки являются отдельными DLL и располагаются в каталоге `Codecs` рядом с основным модулем;
   - просмотрщик при первой необходимости перечисляет `Codecs/*.dll`, загружает их и ищет четыре обязательные экспортируемые функции;
   - кодеки загружаются один раз за сеанс Far Manager, поэтому после установки или замены DLL требуется перезапуск Far.

2. **Публичный ABI**
   - подключение общего заголовка `include/ride_codec_api.h`;
   - версия ABI (`RIDE_CODEC_API_VERSION`) и правила совместимости;
   - C linkage, экспорт символов, соглашение вызова `__cdecl`;
   - точные сигнатуры и назначение `RideCodecGetInfo`, `RideCodecProbe`, `RideCodecDecode` и `RideCodecFreeImage`;
   - устройство структур `RideCodecInfo`, `RideImage` и `RideCodecError`, включая размеры полей и требования к `struct_size`.

3. **Обнаружение формата**
   - `RideCodecGetInfo` сообщает имя кодека и список расширений через точку с запятой;
   - `RideCodecProbe` должен быть быстрым, не выделять большие буферы и не читать за пределами переданного диапазона;
   - при предварительном распознавании Far передаёт до 8192 первых байт, а при окончательном выборе кодека — полный буфер файла;
   - сигнатурные форматы следует распознавать по достаточно строгой проверке заголовка, чтобы не перехватывать чужие файлы;
   - список расширений является описательной метаинформацией и сам по себе не создаёт правило выбора кодека;
   - форматы без сигнатуры требуют отдельного механизма выбора. Текущий специальный случай SCR основан на расширении `.scr` и точной проверке размера в декодере; для нового формата может понадобиться изменение основного модуля.

4. **Декодирование и выходное изображение**
   - `RideCodecDecode` получает полный файл в памяти;
   - успешный результат — непустое изображение с положительными шириной и высотой;
   - единственный формат пикселей ABI v1 — RGBA8, строки сверху вниз, без предварительного умножения RGB на alpha;
   - `stride` задаётся в байтах и должен быть не меньше `width * 4`;
   - `data_size` должен покрывать последнюю читаемую строку: `stride * (height - 1) + width * 4`;
   - кодек обязан проверять переполнение размеров, повреждённые входные данные и чрезмерные размеры изображений;
   - при ошибке возвращать нулевой статус и заполнять `RideCodecError` кодом, смещением и понятным сообщением.

5. **Владение памятью и граница DLL**
   - память пикселей освобождается только через `RideCodecFreeImage` той же DLL, которая её выделила;
   - функция освобождения должна безопасно обрабатывать пустой результат, в том числе после неудачного декодирования;
   - нельзя передавать через ABI C++ объекты, исключения, STL-контейнеры или владение памятью между разными runtime;
   - исключения не должны пересекать границу DLL.

6. **Сборка и установка**
   - минимальный пример CMake-цели для `.dll`, настройки include path и определения `RIDE_CODEC_BUILD`;
   - требования к архитектуре DLL и совместимости с Windows/Far Manager;
   - размещение DLL в `Plugins/FarRideViewer/Codecs/`;
   - пояснение о зависимостях кодека и необходимости поставлять их вместе с DLL;
   - пример независимого добавления DLL без пересборки `FarRideViewer.dll`.

7. **Тестирование**
   - тесты положительного и отрицательного распознавания;
   - проверки ориентации изображения, RGBA/alpha, stride и размеров буфера;
   - тесты некорректных, усечённых и чрезмерно больших входных данных;
   - проверка освобождения памяти и повторных вызовов;
   - подключение теста к CTest и проверка в GitHub Actions;
   - ручной тест открытия через F3 и F11 в обычной панели, временной панели и результатах Alt+F7.

8. **Полный пример**
   - добавить минимальный исходник простого кодека, реализующий все четыре экспортируемые функции;
   - показать команды сборки, структуру выходных файлов и установку;
   - отдельно описать, в каких случаях достаточно добавить DLL, а в каких требуется расширить host.
