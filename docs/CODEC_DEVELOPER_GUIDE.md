# Руководство разработчика: сторонний кодек для Far Ride Viewer

## 1. Назначение

Far Ride Viewer отделяет интерфейс FAR и работу с окном просмотра от декодирования изображений. Основной модуль `FarRideViewer.dll` загружает кодеки как независимые DLL через C ABI v1, объявленный в `include/ride_codec_api.h`.

Это позволяет добавить новый формат без изменения и пересборки основного просмотрщика — при условии, что формат можно надёжно определить по переданным байтам и он укладывается в текущий контракт RGBA8.

В руководстве описаны текущая реализация ABI v1 и порядок создания модуля под Windows/MSYS2 UCRT64. Исходник небольшого рабочего примера находится в `examples/ppm_codec/`: он декодирует ограниченное подмножество бинарного PPM P6 и содержит отдельный тест.

## 2. Как host находит кодеки

При первой проверке файла host:

1. Вычисляет каталог, в котором находится `FarRideViewer.dll`.
2. Перечисляет DLL непосредственно в подкаталоге `Codecs` (маска `Codecs\\*.dll`; вложенные каталоги не сканируются).
3. Загружает DLL через `LoadLibraryW`.
4. Ищет четыре экспортируемых символа: `RideCodecGetInfo`, `RideCodecProbe`, `RideCodecDecode` и `RideCodecFreeImage`.
5. Вызывает `RideCodecGetInfo`, проверяет размер структуры и точное совпадение версии ABI.
6. Сохраняет указатели на функции и держит модуль загруженным для последующих декодирований.

DLL без любой из четырёх функций, с ошибкой `LoadLibraryW`, неверной версией ABI или неподходящим `struct_size` пропускается. Каталог и список модулей кэшируются на весь сеанс FAR: после добавления, удаления или замены DLL FAR нужно полностью перезапустить.

### Два этапа распознавания

До передачи F3 FAR вызывает предварительную проверку: host читает не более первых **8192 байт** файла и передаёт этот префикс в `RideCodecProbe(data, size)`. Значение `size` равно фактически прочитанному числу байт и может быть меньше 8192, например для короткого файла.

При открытии изображения host читает файл целиком в память и повторно вызывает `Probe` с полным буфером. Сначала проверяются кодеки, объявившие расширение файла; если они не распознали содержимое, проверяются остальные кодеки. Расширение влияет только на приоритет, но не заменяет `Probe`: выбрать кодек можно только после успешного ответа его функции распознавания.

Следствия для реализации:

- `Probe` обязан корректно работать на коротком префиксе и никогда не читать байты за пределами `size`.
- Проверка должна быть быстрой, детерминированной и не должна выделять большие буферы.
- Используйте максимально специфичную сигнатуру и проверяйте обязательные поля заголовка. Ложное совпадение может перехватить чужой формат.
- `Probe` получает только указатель и длину, без имени или пути. Поэтому не пытайтесь определять расширение внутри кодека.
- Не требуйте, чтобы заголовок целиком помещался в 8192 байта. Окончательную валидацию выполняйте при проверке полного буфера и в `Decode`.

### Форматы без сигнатуры

Поле `extensions` в `RideCodecInfo` используется host как универсальная подсказка при поиске кодека. Оно содержит расширения через точку с запятой, без точки в начале; сравнение выполняется без учёта регистра.

На этапе предварительного F3-распознавания host сначала вызывает `Probe` у кодеков, объявивших расширение файла, затем у остальных. Если ни один кодек не распознал первые 8192 байта, совпадение с объявленным расширением может разрешить открытие просмотрщика. Это только подсказка: при фактической загрузке файла host передаёт полный буфер в `Probe`, и кодек без успешного ответа выбран не будет.

ZX Spectrum SCR работает по этому же общему механизму: `zx_spectrum.dll` объявляет расширение `scr`, а его `Probe` подтверждает только файлы размером ровно 6144 или 6912 байт. Основной модуль не содержит отдельного правила для SCR.

Для нового headerless-формата достаточно объявить расширение в `RideCodecGetInfo` и реализовать `Probe`, который проверяет доступные данные (например, точный размер или структуру полного файла). Специальное изменение host не требуется.

## 3. Публичный ABI v1

Всегда подключайте общий заголовок:

~~~cpp
#include "ride_codec_api.h"
~~~

Не копируйте определения структур в собственный проект и не меняйте заголовок локально. Он является источником истины для расположения полей, типов, соглашения вызова и экспортных атрибутов.

### Версия и экспорт

- `RIDE_CODEC_API_VERSION` сейчас равен `1u`. Host принимает только точное совпадение версии.
- На стороне кодека при сборке обязательно определять `RIDE_CODEC_BUILD`: заголовок тогда помечает функции как `__declspec(dllexport)`.
- Все функции имеют C linkage (`extern "C"`) и соглашение вызова `__cdecl`, заданное макросом `RIDE_CODEC_CALL`.
- Не экспортируйте C++ классы, STL-контейнеры, исключения или C++ ABI.
- DLL должна быть собрана для той же архитектуры и совместимой среды выполнения, что и FAR. Текущий проект собирается MinGW-w64 в MSYS2 UCRT64.

### Структуры

| Структура | Поля ABI v1 | Назначение |
|---|---|---|
| `RideCodecInfo` | `uint32_t struct_size`, `uint32_t api_version`, `char name[64]`, `char extensions[128]` | Метаданные DLL |
| `RideImage` | `uint32_t struct_size`, `width`, `height`, `stride`, `pixel_format`, `uint8_t *pixels`, `size_t data_size` | Результат декодирования |
| `RideCodecError` | `uint32_t code`, `size_t byte_offset`, `char message[160]` | Диагностика ошибки |

Поля `width`, `height`, `stride` и `pixel_format` имеют тип `uint32_t`. `data_size` и `byte_offset` имеют тип `size_t`, а значит зависят от разрядности процесса. Не упаковывайте структуры через `#pragma pack` и не меняйте порядок полей.

Перед записью в `RideCodecInfo` или `RideImage` проверяйте входное поле `struct_size`: оно должно быть не меньше `sizeof(соответствующая_структура)`. Host перед вызовом передаёт размер своей структуры. При очистке результата сохраните переданное значение `struct_size`; не затирайте его нулём. Успешный `GetInfo` должен вернуть собственный `sizeof(RideCodecInfo)` в поле `struct_size`.

### Четыре экспортируемые функции

~~~cpp
uint32_t RIDE_CODEC_CALL RideCodecGetInfo(RideCodecInfo *info);
uint32_t RIDE_CODEC_CALL RideCodecProbe(const uint8_t *data, size_t size);
uint32_t RIDE_CODEC_CALL RideCodecDecode(
    const uint8_t *data, size_t size,
    RideImage *out, RideCodecError *error);
void RIDE_CODEC_CALL RideCodecFreeImage(RideImage *image);
~~~

Экспортные объявления в заголовке содержат `RIDE_CODEC_EXPORT`. В реализации используйте ту же форму, что и встроенные кодеки.

**RideCodecGetInfo**

Возвращает ненулевое значение при успехе. Заполняет:

- `name` — короткое имя кодека; используйте UTF-8 и завершающий нулевой байт.
- `extensions` — расширения через точку с запятой, без точки в начале, например `ppm;pnm`.

Не помещайте в эти поля длинные строки. Это описание модуля, а не список возможностей для выбора по расширению.

**RideCodecProbe**

Возвращает ненулевое значение, если переданный диапазон похож на формат, который поддерживает модуль. В остальных случаях возвращает ноль. Функция не должна декодировать всё изображение или доверять одним только размерам неподписанного файла.

**RideCodecDecode**

Получает полный файл в памяти. При успехе возвращает ненулевое значение и заполняет `RideImage`. При ошибке возвращает ноль и записывает диагностику в `RideCodecError`, если указатель ошибки не равен `nullptr`.

**RideCodecFreeImage**

Освобождает память, выделенную `Decode`. Освобождение выполняется через ту же DLL, которая выделила буфер. Функция должна безопасно принимать `nullptr`, пустую структуру и повторное освобождение уже очищенного результата.

## 4. Контракт выходного изображения

В ABI v1 поддерживается только `pixel_format = 1`, то есть **RGBA8**:

- один пиксель — четыре байта в порядке R, G, B, A;
- строки идут сверху вниз (top-down);
- RGB не должен быть предварительно умножен на alpha (straight / non-premultiplied alpha);
- полностью непрозрачные форматы должны выдавать alpha = 255;
- альфа-канал исходника нужно сохранять, а не отбрасывать.

Размеры `width` и `height` должны быть положительными. `stride` задаётся в байтах и должен быть не меньше `width * 4`. Допускается дополнительное выравнивание строк, но `data_size` должен покрывать как минимум последний читаемый байт:

`required = stride * (height - 1) + width * 4`

Проверяйте произведения и суммы до выделения памяти: используйте 64-битные промежуточные значения и проверяйте переполнение перед приведением к `uint32_t` или `size_t`. Host дополнительно проверяет размеры, формат пикселей, stride и минимальный объём буфера, после чего копирует строки в собственную память.

Установите разумные ограничения на максимальную ширину, высоту и общее число пикселей. Это защищает от повреждённых файлов и входных данных, провоцирующих чрезмерные выделения памяти.

## 5. Ошибки и владение памятью

Коды ошибок не являются глобальным перечислением ABI: кодек может определить собственные числовые значения. Рекомендуется выделить отдельные коды для некорректного заголовка, неподдерживаемого варианта, усечения данных, неверных размеров, превышения лимита пикселей и ошибки выделения памяти.

- `code` — ненулевой код ошибки.
- `byte_offset` — смещение в исходном файле, если его можно определить; иначе 0.
- `message` — короткое сообщение в UTF-8 с завершающим нулём.

При неудаче очистите `RideImage`: указатель пикселей должен быть `nullptr`, размеры, stride, формат и data_size — нулевыми; сохраните `struct_size`, переданный host. Освободите все частичные выделения до возврата.

Host вызывает `RideCodecFreeImage` после вызова `Decode`, в том числе после неудачного декодирования. Поэтому `FreeImage` обязана быть безопасной для пустого результата. Она не должна освобождать чужую память или предполагать, что декодирование завершилось успешно.

Никогда не выделяйте буфер в одной DLL и не освобождайте его через `delete`, `free` или allocator другой DLL. Выделяйте и освобождайте память внутри одного модуля. Не позволяйте C++ исключениям пересекать границу DLL: перехватывайте их внутри экспортируемой функции и возвращайте обычный код ошибки.

## 6. Сборка отдельной DLL

Новый кодек может собираться отдельно от основного проекта. Это основной путь для стороннего разработчика: достаточно иметь исходники Far Ride Viewer, чтобы подключить общий заголовок, и подходящий MSYS2 UCRT64 toolchain.

Посмотрите готовый пример в `examples/ppm_codec/CMakeLists.txt`. Его существенные части:

~~~cmake
add_library(my_codec SHARED my_codec.cpp)
target_include_directories(my_codec PRIVATE
  "${FAR_RIDE_VIEWER_ROOT}/include"
)
target_compile_features(my_codec PRIVATE cxx_std_17)
target_compile_definitions(my_codec PRIVATE
  RIDE_CODEC_BUILD WIN32_LEAN_AND_MEAN NOMINMAX
)
set_target_properties(my_codec PROPERTIES
  PREFIX ""
  OUTPUT_NAME "my_codec"
  SUFFIX ".dll"
  RUNTIME_OUTPUT_DIRECTORY "${CMAKE_BINARY_DIR}/Codecs"
  LIBRARY_OUTPUT_DIRECTORY "${CMAKE_BINARY_DIR}/Codecs"
)
~~~

Для MinGW проект использует статическую линковку стандартных C++ runtime-библиотек, чтобы не создавать лишнюю зависимость от локальных DLL компилятора. Если кодек использует стороннюю DLL, её необходимо поставлять рядом с кодеком или иным корректным способом обеспечить её загрузку; отсутствие зависимости приведёт к ошибке `LoadLibraryW`.

Сборка примера из корня репозитория в терминале MSYS2 UCRT64:

~~~bash
cmake -S examples/ppm_codec -B build-ppm -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DFAR_RIDE_VIEWER_ROOT="$PWD"

cmake --build build-ppm --target ppm_codec ppm_codec_test
ctest --test-dir build-ppm --output-on-failure
~~~

DLL примера появится в `build-ppm/Codecs/ppm.dll`. Скопируйте её в каталог `Plugins/FarRideViewer/Codecs/` установленного FAR. Перезапустите FAR и откройте PPM-файл. Для этого отдельного кодека не нужно пересобирать `FarRideViewer.dll` или остальные кодеки.

Если кодек добавляется непосредственно в этот репозиторий как штатная возможность, дополнительно внесите его target в корневой `CMakeLists.txt`, добавьте тест в CTest и настройте CI. Отдельная DLL всё равно остаётся независимым runtime-модулем.

## 7. Тестирование нового кодека

Проверки должны быть как минимум на уровне ABI и декодера. Используйте маленькие синтетические входные данные с заранее известными пикселями — они позволяют проверять точные значения, ориентацию строк и альфа-канал.

Минимальный набор:

1. `GetInfo`: успешный вызов, версия ABI, корректные строки и завершающие нули.
2. `Probe`: положительный и отрицательный примеры; короткие префиксы; данные длиной 0, 1 и меньше минимального заголовка.
3. `Decode`: реальные файлы и синтетические случаи, проверка width/height, формата, stride, data_size, порядка строк и RGBA.
4. Ошибки: неверная сигнатура, усечённый заголовок, усечённый raster/поток, некорректные размеры, переполнение, неизвестные варианты и чрезмерное число пикселей.
5. Память: освобождение успешного результата, безопасное освобождение после неудачи, повторное освобождение, многократные циклы decode/free.
6. Интеграция: DLL действительно загружается FAR, файл определяется предварительным Probe и открывается через F3 и F11.

Не ограничивайтесь проверкой `Probe`: он может правильно распознать файл, который затем не декодируется. Не ограничивайтесь и синтетическими файлами: добавьте хотя бы один реальный пример каждого поддерживаемого варианта. Для декодеров недоверенных входных данных особенно важны усечённые и повреждённые файлы.

При добавлении штатного кодека подключите тест к CTest через `add_test`. Текущий GitHub Actions workflow `.github/workflows/build.yml` собирает все цели и запускает `ctest --test-dir build --output-on-failure` в MSYS2 UCRT64.

## 8. Полный минимальный пример

В каталоге `examples/ppm_codec/` находятся три файла:

- `ppm_codec.cpp` — полноценная DLL для ограниченного бинарного PPM P6;
- `ppm_codec_test.cpp` — тест API, точных пикселей, отрицательного распознавания и безопасного освобождения;
- `CMakeLists.txt` — независимая сборка DLL и теста.

Пример поддерживает P6, max value 255, размеры не более 32768 на сторону и не более 100 миллионов пикселей. Он намеренно строго проверяет точный размер raster и не претендует на поддержку всех допустимых вариантов PPM/PNM. Это учебный модуль для демонстрации ABI, а не универсальная реализация Netpbm.

## 9. Когда потребуется изменить основной модуль

В большинстве случаев достаточно положить новую DLL в `Codecs`. Основной модуль нужно менять, если требуется:

- распознавание формата без сигнатуры по расширению или по внешним метаданным;
- специальный приоритет выбора между конфликтующими кодеками;
- дополнительный тип выходного изображения, например индексированный буфер, иной порядок каналов или аппаратный ресурс (ABI v1 этого не поддерживает);
- новый ABI с дополнительными возможностями, которые нельзя представить в текущих структурах;
- новое поведение просмотра, например воспроизведение анимации или многостраничность.

Не расширяйте текущую структуру локально и не меняйте `RIDE_CODEC_API_VERSION` только в одном кодеке. Изменение ABI должно быть согласованным изменением общего заголовка, host и всех совместимых модулей.

## 10. Контрольный список перед публикацией кодека

- [ ] DLL собрана для той же архитектуры, что и FAR.
- [ ] Все четыре экспортируемые функции видны в таблице экспортов DLL.
- [ ] ABI версия и `struct_size` корректны.
- [ ] `Probe` работает на префиксе до 8192 байт и не читает за его пределами.
- [ ] Сигнатура специфична; ложные совпадения с другими форматами исключены.
- [ ] Успешный результат — top-down RGBA8 с корректным stride и data_size.
- [ ] Размеры проверены на переполнение и ограничены разумным pixel limit.
- [ ] Ошибки не оставляют частично выделенную память.
- [ ] `FreeImage` безопасен для пустого и повторно очищаемого результата.
- [ ] Исключения не выходят за границу DLL.
- [ ] Есть тесты положительного, отрицательного, повреждённого и усечённого ввода.
- [ ] Проверена загрузка реальной DLL через F3 и F11 в FAR.
- [ ] Все сторонние зависимости и лицензии поставляются корректно.
