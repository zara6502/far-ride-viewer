## 3. Подготовка ветки к итоговому PR

После одобрения плана:

1. Проверить, что рабочее дерево локальной копии чистое и все нужные коммиты отправлены на origin.
2. Получить актуальный `main`.
3. Переключиться на `feature/jpeg-stb-image` и выполнить обычное слияние `origin/main` в рабочую ветку (без rebase и переписывания истории). Это должно добавить два main-only коммита; пять совпадающих тестовых изображений уже имеют одинаковое содержимое.
4. Проверить merge diff, статус ветки и список изменённых файлов. Убедиться, что не появились удаления, дубликаты или неожиданные конфликты.
5. Только после этого изменить base PR #4 на `main` и проверить полный diff PR.

Предпочтительно не переписывать историю рабочей ветки: PR #2 → #3 → #4 уже образуют цепочку и содержат последовательные исправления и регрессионные тесты.

## 4. Обязательная проверка перед Merge

### Автоматические проверки

- Чистая конфигурация и полная сборка корневого проекта в MSYS2 UCRT64.
- Полный корневой CTest: QOI/QOIMT, PCX, stb_image, ZX Spectrum SCR.
- Независимая сборка примера PPM-кодека из `examples/ppm_codec`.
- Отдельный CTest примера PPM.
- Успешный GitHub Actions на итоговом HEAD после синхронизации с `main`.
- Просмотр предупреждений компилятора, а не только итогового exit code.

Команды для повторной локальной проверки из корня репозитория:

```bash
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release \
  -DFAR_SOURCE_DIR="$PWD/../FarManager"
cmake --build build
ctest --test-dir build --output-on-failure

cmake -S examples/ppm_codec -B build-ppm -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DFAR_RIDE_VIEWER_ROOT="$PWD"
cmake --build build-ppm --target ppm_codec ppm_codec_test
ctest --test-dir build-ppm --output-on-failure
```

### Ручные проверки в FAR

- F3 в обычной панели и открытие через F11.
- F3 из временной панели.
- F3 в диалоге результатов Alt+F7, включая выбранную строку файла и разбор полного пути.
- Команда `ride:` с путями в кавычках, пробелами и Unicode.
- QOI/QOIMT, PCX, BMP, TGA, JPEG baseline/progressive, PNG с альфа-каналом, GIF (первый кадр) и оба варианта SCR.
- Отсутствующий каталог `Codecs`, отсутствующая DLL, DLL без обязательных exports, неподходящая версия ABI и неподдерживаемый файл.
- Перезапуск FAR после установки или замены DLL (список кодеков кэшируется на сеанс).

## 5. Оставшиеся замечания аудита

- В roadmap пока не отмечены как выполненные проверки повреждённых и усечённых GIF.
- Автоматические тесты проверяют кодеки и PPM-пример, но не заменяют ручную проверку всех FAR-сценариев из раздела выше.
- При нескольких DLL, распознающих один файл, фактический выбор зависит от порядка загрузки файлов; отдельный контракт приоритетов между кодеками не определён. Для текущего набора нужно убедиться, что это не создаёт пересечений.
- При финальном аудите следует проверить лицензии и атрибуцию vendored `stb_image` и заимствованной логики ZX Spectrum SCR.

Эти пункты не означают, что текущая сборка неработоспособна; это проверки и ограничения, которые следует закрыть или явно принять перед публикацией.
