# Ride Codec API v1

[English version](CODEC_API.md)

Этот документ описывает C ABI, через который Far Ride Viewer загружает DLL-кодеки и декодирует файлы изображений.

## 1. Общая схема

Каждый кодек представляет собой отдельную DLL Windows, размещённую в каталоге `Codecs` рядом с `FarRideViewer.dll`.

При запуске host просматривает этот каталог и ищет файлы `*.dll`. Модуль принимается только в том случае, если он экспортирует все четыре обязательные функции, сообщает поддерживаемую версию API и возвращает корректные метаданные.

API состоит из четырёх функций:

1. **GetInfo** — возвращает имя кодека и поддерживаемые расширения файлов.
2. **Probe** — определяет, относится ли переданный буфер байтов к формату кодека.
3. **Decode** — декодирует полный файл в стандартный буфер пикселей.
4. **FreeImage** — освобождает память, выделенную кодеком.

Текущая версия API — `1` (`RIDE_CODEC_API_VERSION`).

## 2. Заголовок и ABI платформы

Подключите:

```cpp
#include "ride_codec_api.h"
```

Заголовок определяет соглашение о вызовах и экспорте:

- `RIDE_CODEC_EXPORT` — `__declspec(dllexport)` при сборке DLL-кодека и `__declspec(dllimport)` при подключении.
- `RIDE_CODEC_CALL` — `__cdecl` в Windows.
- `RIDE_CODEC_API_VERSION` — текущая версия `1u`.
- `RIDE_CODEC_NAME_CAPACITY` — 64 байта.
- `RIDE_CODEC_EXTENSIONS_CAPACITY` — 128 байт.

Публичные функции используют C linkage. DLL должна собираться с совместимой архитектурой и ABI; текущий проект ориентирован на Windows и MinGW-w64.

## 3. Структуры данных

### `RideCodecInfo`

```cpp
typedef struct RideCodecInfo {
    uint32_t struct_size;
    uint32_t api_version;
    char name[64];
    char extensions[128];
} RideCodecInfo;
```

| Поле | Назначение |
|---|---|
| `struct_size` | Размер структуры в байтах. Перед вызовом `RideCodecGetInfo` вызывающая сторона записывает доступный размер; кодек возвращает размер своей структуры. |
| `api_version` | Версия API, реализованная кодеком. Должна совпадать с `RIDE_CODEC_API_VERSION`. |
| `name` | Человекочитаемое имя кодека в виде UTF-8 строки с завершающим нулевым байтом. |
| `extensions` | Расширения файлов через точку с запятой, без точек в начале; например `bmp;tga;jpg`. |

Host показывает имя и расширения на экране F1. Сравнение расширений выполняется без учёта регистра; они используются только для определения порядка проверки кодеков.

### `RideImage`

```cpp
typedef struct RideImage {
    uint32_t struct_size;
    uint32_t width;
    uint32_t height;
    uint32_t stride;
    uint32_t pixel_format;
    uint8_t* pixels;
    size_t data_size;
} RideImage;
```

| Поле | Назначение |
|---|---|
| `struct_size` | Размер структуры. Host инициализирует его перед вызовом `RideCodecDecode`; кодек должен сохранить переданное вызывающей стороной значение. |
| `width`, `height` | Размеры декодированного изображения в пикселях; оба значения должны быть ненулевыми. |
| `stride` | Расстояние в байтах между началами соседних строк. |
| `pixel_format` | Должно быть равно `1`, что означает top-down RGBA8. |
| `pixels` | Указатель на первый пиксель (левый верхний угол). |
| `data_size` | Размер выделенного буфера пикселей в байтах. |

Для одной строки требуется `width * 4` байт. Значение stride должно быть не меньше этого размера. Буфер должен содержать как минимум `stride * (height - 1) + width * 4` байт.

RGBA8 означает четыре 8-битных канала в порядке R, G, B, A. Строки хранятся сверху вниз: первая строка соответствует верхней части изображения. Альфа-канал прямой (не premultiplied).

### `RideCodecError`

```cpp
typedef struct RideCodecError {
    uint32_t code;
    size_t byte_offset;
    char message[160];
} RideCodecError;
```

| Поле | Назначение |
|---|---|
| `code` | Код ошибки, определяемый конкретным кодеком. |
| `byte_offset` | Смещение байта, связанное с ошибкой, если оно известно. |
| `message` | Диагностическое сообщение UTF-8 с завершающим нулевым байтом. |

При ошибке декодирования host показывает эти поля. Коды ошибок определяются отдельными кодеками; общей перечислимой константы в API v1 нет.

## 4. Обязательные экспортируемые функции

Все четыре функции должны экспортироваться с C linkage и объявленным соглашением о вызовах.

```cpp
uint32_t RIDE_CODEC_CALL RideCodecGetInfo(RideCodecInfo* info);

uint32_t RIDE_CODEC_CALL RideCodecProbe(
    const uint8_t* data,
    size_t size
);

uint32_t RIDE_CODEC_CALL RideCodecDecode(
    const uint8_t* data,
    size_t size,
    RideImage* out,
    RideCodecError* error
);

void RIDE_CODEC_CALL RideCodecFreeImage(RideImage* image);
```

### 4.1 `RideCodecGetInfo`

Возвращает метаданные кодека.

- Host устанавливает `info->struct_size = sizeof(RideCodecInfo)`.
- При успехе функция возвращает ненулевое значение, при ошибке — ноль.
- Необходимо отклонять нулевой указатель и структуру меньшего размера, чем ожидает кодек.
- Установите `struct_size` равным `sizeof(RideCodecInfo)`, а `api_version` — `RIDE_CODEC_API_VERSION`.
- Обе строки должны завершаться нулевым байтом.
- Расширения перечисляются без точек, разделитель — точка с запятой.

Host отклоняет модули, версия API которых не совпадает с его собственной.

### 4.2 `RideCodecProbe`

Проверяет, принадлежат ли переданные байты формату кодека.

- Верните ненулевое значение, если данные распознаны, иначе верните ноль.
- Входной указатель доступен только для чтения и может быть нулевым при `size == 0`.
- Нельзя читать за пределами `size`.
- Функция должна безопасно обрабатывать короткие и усечённые префиксы.
- Функция не получает имя или расширение файла и должна анализировать только байты.

Host вызывает `Probe` в два этапа:

1. **Предварительная проверка для F3:** читаются первые 8192 байта (или меньше, если файл короче) и вызываются функции распознавания. Если ни один кодек не распознал префикс, совпадающее объявленное расширение всё ещё может разрешить открыть просмотрщик. Это только предварительное решение.
2. **Фактическая загрузка:** после чтения файла целиком host повторно вызывает функции распознавания, передавая полный буфер. Кодек выбирается только при успешном ответе его `Probe`.

Сначала проверяются кодеки, объявившие расширение файла. Если ни один из них не распознал данные, проверяются остальные кодеки. Расширение не может заменить успешное распознавание полного файла.

Двухэтапная схема позволяет работать и с форматами, чья идентифицирующая структура не помещается в первые 8192 байта. Например, JPEG frame header или данные PNG могут находиться дальше из-за большого объёма метаданных.

### 4.3 `RideCodecDecode`

Декодирует полный файл из памяти.

- `data` указывает на полное содержимое файла, `size` содержит его точную длину.
- Host инициализирует `out` значением `out->struct_size = sizeof(RideImage)`.
- При успехе функция возвращает ненулевое значение, при ошибке — ноль.
- При успехе заполните все поля `RideImage` и верните корректный буфер top-down RGBA8.
- При ошибке заполните `RideCodecError`, если указатель `error` не равен null.
- При очистке или заполнении структуры сохраните переданное host значение `out->struct_size`.
- Перед вычислением размеров, stride и объёма выделения памяти проверяйте арифметику на переполнение.

Перед использованием изображения host проверяет структуру результата, размеры, формат пикселей, stride и размер буфера.

### 4.4 `RideCodecFreeImage`

Освобождает буфер изображения, выделенный кодеком.

- Host вызывает эту функцию из той же DLL, которая выполнила декодирование.
- Вызов возможен как после успешного, так и после неудачного `RideCodecDecode`.
- Функция должна безопасно обрабатывать нулевой указатель и пустую/частично инициализированную структуру.
- Освобождать можно только память, принадлежащую этому кодеку.
- После освобождения по возможности обнулите указатель и поля размера.

Не используйте аллокатор host или другой DLL для памяти, которую должна освобождать эта функция.

## 5. Владение памятью и время жизни

Память, возвращаемая в `RideImage::pixels`, принадлежит кодеку. Host копирует проверенные пиксели RGBA8 в собственное хранилище, после чего вызывает `RideCodecFreeImage`.

DLL кодека должна оставаться загруженной до освобождения возвращённого изображения. Host сохраняет модуль кодека загруженным на протяжении всего времени его регистрации.

Нельзя возвращать указатели на стековую память, временные буферы или память, время жизни которой заканчивается при возврате из `RideCodecDecode`.

## 6. Минимальный каркас реализации

```cpp
#include "ride_codec_api.h"

#include <cstring>
#include <new>

extern "C" RIDE_CODEC_EXPORT uint32_t RIDE_CODEC_CALL
RideCodecGetInfo(RideCodecInfo* info)
{
    if (!info || info->struct_size < sizeof(RideCodecInfo))
        return 0;

    RideCodecInfo value{};
    value.struct_size = sizeof(value);
    value.api_version = RIDE_CODEC_API_VERSION;
    std::strncpy(value.name, "Example", sizeof(value.name) - 1);
    std::strncpy(value.extensions, "example;ex", sizeof(value.extensions) - 1);
    *info = value;
    return 1;
}

extern "C" RIDE_CODEC_EXPORT uint32_t RIDE_CODEC_CALL
RideCodecProbe(const uint8_t* data, size_t size)
{
    return data && size >= 4 &&
           data[0] == 'E' && data[1] == 'X' &&
           data[2] == 'A' && data[3] == 'M';
}

extern "C" RIDE_CODEC_EXPORT uint32_t RIDE_CODEC_CALL
RideCodecDecode(const uint8_t* data, size_t size,
                RideImage* out, RideCodecError* error)
{
    // Проверить вход и выход, декодировать полный файл,
    // выделить top-down RGBA8 буфер и заполнить все поля RideImage.
    // Вернуть 1 при успехе или 0 при ошибке.
    (void)data; (void)size; (void)out; (void)error;
    return 0;
}

extern "C" RIDE_CODEC_EXPORT void RIDE_CODEC_CALL
RideCodecFreeImage(RideImage* image)
{
    if (!image)
        return;
    delete[] image->pixels;
    image->pixels = nullptr;
    image->data_size = 0;
}
```

Это структурный каркас, а не готовый декодер.

## 7. Правила загрузки и выбора кодека

- Host просматривает `Codecs\\*.dll` рядом с DLL плагина.
- DLL должна экспортировать все четыре обязательных символа.
- `RideCodecGetInfo` должен завершиться успешно и сообщить версию API 1.
- Имя кодека и список расширений показываются на экране F1.
- Расширения сравниваются без учёта регистра.
- Совпадающее расширение влияет только на порядок вызова `Probe`.
- Перед декодированием обязательно успешное распознавание полного файла через `RideCodecProbe`.
- В API v1 нет отдельного настраиваемого контракта приоритетов на случай, когда один файл распознают несколько кодеков.

Список кодеков кэшируется на текущий сеанс Far Manager. После добавления, удаления или замены DLL перезапустите Far Manager.

## 9. Совместимость

API v1 — фиксированный контракт C ABI. Host отклоняет кодек, сообщающий другую версию API. Если несовместимо меняются структуры, соглашение о вызовах, контракт формата пикселей или обязательные экспорты, следует вводить новую версию API, а не менять поведение версии 1 без изменения номера.

Практические инструкции по интеграции и отдельный пример PPM-кодека находятся в [руководстве разработчика кодеков](CODEC_DEVELOPER_GUIDE.md).
